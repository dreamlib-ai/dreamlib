# Security

Dreamlib stores dreams, which are private and can be sensitive. We take reports seriously.

## Reporting a problem

Please do not open a public issue for a security problem. Use GitHub's private vulnerability reporting on this repository (Security tab, "Report a vulnerability"). Include what you found, how to reproduce it, and what you think the impact is.

We aim to reply within a few days, keep you informed while we fix it, and credit you if you want.

## What counts

- Reading, changing or deleting another person's dreams, images or account data
- Getting around consent levels: a private or collective dream becoming visible to others
- Leaking dream text through logs, errors, similarity evidence or shared pages
- Authentication or authorization bypass
- Secrets exposed in the repository or in a release
- Ways to run up provider costs past the daily allowances

## What we ask

- Use your own account or a test account. Do not access other people's data.
- Stop and report as soon as you can show the problem.
- Give us reasonable time to fix it before you publish.

## Keys and data

No keys, project identifiers or user data belong in this repository. If you see any, report it the same way.
